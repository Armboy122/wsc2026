# ผลตรวจห้องทดลอง Knowledge

ตรวจวันที่ 10 กันยายน 2026 บน Python 3.12 หลังติดตั้งด้วย `uv sync` ใช้เวอร์ชันใน `uv.lock`

## สิ่งที่ตรวจแล้ว

- `uv run pytest -q`: ผ่าน 20 รายการ ครอบคลุมการค้น เอกสารเต็ม การถามต่อ ตัวกรองสถานะและวันที่ เอกสารเปลี่ยน checksum พาธออกนอกโฟลเดอร์ งบขนาดเอกสาร สิทธิ์ผู้ใช้ การเข้ารหัสประวัติ การเขียนเซสชันพร้อมกัน การลบประวัติ หลักฐานปลอม provider ล้มเหลว และสัญญาปลั๊กอินอ่านเพิ่มเติม
- `uv run python scripts/evaluate_retrieval.py`: พบเอกสารเป้าหมายในสามอันดับแรก 4/4 ตัวอย่าง จาก corpus 45 ไฟล์ เป็นคำถามตรงหัวข้อชุดเล็ก ไม่ใช่ตัวแทนความแม่นยำการค้นทั้งหมด
- CLI ค้นและแสดงหลักฐานคำถามขอคืนเงินประกันรันได้จริงจาก corpus ร่วมที่รากรีโป
- ทดสอบ API ผ่าน TestClient รวมการปฏิเสธ token ไม่ถูกต้องและการอ่านเซสชันของผู้อื่น ไม่ได้เปิดบริการสาธารณะ
- การเรียก Gemini ทดสอบด้วย HTTP transport จำลองเฉพาะในชุดทดสอบ ไม่มีการเรียกบัญชี Gemini จริง จึงยังไม่ยืนยันชื่อโมเดล เวลาแฝง ค่าใช้จ่าย หรือคุณภาพภาษาไทย
- มี deprecation warning 2 รายการจากเครื่องมือทดสอบ Starlette/httpx และ AnyIO ไม่ทำให้การทดสอบล้มเหลว

## เกณฑ์ก่อนขยายขอบเขต

1. ให้เจ้าของเนื้อหาตรวจเอกสารและเลือกฉบับที่เชื่อถือได้ โดยเฉพาะอัตราและวันที่มีผล
2. รวบรวมคำถามจริงอย่างน้อย 30 ข้อ รวมคำถามกำกวม ข้อมูลไม่ครบ คำถามนอกเอกสาร และการเปลี่ยนหัวข้อในเซสชันเดียว
3. ทดลอง Gemini จริง จดเอกสารที่เลือก คำตอบ หลักฐาน เวลา และข้อผิดพลาด แยกความผิดพลาดจากการค้นกับการสรุป
4. ตกลงเกณฑ์รับงานตามผลจริงก่อนต่อเสียง ส่วน OMS/VOC ให้รอความสามารถและสัญญาระบบจริงก่อนเริ่มปลั๊กอิน

เพิ่ม regression: เมื่อเอกสารอันดับแรกเกินงบขนาด ต้องเลือกเอกสารที่เล็กกว่าจากอันดับถัดไปได้

## งานที่พักไว้

OMS, VOC, การสร้างหรือแก้คำร้อง, การติดตามสถานะจากระบบจริง, การส่งข้อความแจ้งเตือน, เครื่องมือเขียนข้อมูล และ realtime audio ไม่มีการอ้างว่าพร้อมใช้งานหรือทดสอบแล้ว
