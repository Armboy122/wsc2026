# ห้องทดลอง Knowledge

ขอบเขตปัจจุบันคือค้นเอกสารและถามตอบพร้อมหลักฐาน เพื่อทดสอบคุณภาพ Knowledge ก่อนต่อระบบอื่น ชื่อแพ็กเกจยังเป็น `voice_assistant` แต่รุ่นนี้ไม่มีระบบเสียง

**พัก OMS, VOC และการเชื่อมระบบภายนอกทั้งหมด** ไม่มีการสร้างคำร้องจำลอง ไม่มีผลสำเร็จสมมติ และยังไม่มีระบบติดตามงานหรือส่งข้อความ ปลั๊กอินปัจจุบันทำได้เฉพาะอ่านข้อมูล

## เริ่มทดลอง

ใช้ Python 3.12 ขึ้นไป เปิดเทอร์มินัลในรีโป `wsc2026` แล้วเข้า `labs/knowledge`:

```bash
cd labs/knowledge
uv sync --locked
uv run python scripts/setup_lab.py
uv run python -m voice_assistant.cli search "ขอคืนเงินประกันการใช้ไฟฟ้าต้องทำอย่างไร"
uv run python -m voice_assistant.cli chat
```

สคริปต์ตั้งค่าสร้าง `.env` พร้อมกุญแจเข้ารหัสและ API token เฉพาะเครื่อง ไม่เขียนทับไฟล์เดิม โหมดเริ่มต้น `extractive` แสดงข้อความจากเอกสารและที่มา **ยังไม่ใช่คำตอบจากโมเดล AI** ใช้ตรวจว่าค้นเอกสารถูกหรือไม่ก่อนเสียค่าเรียกโมเดล

พิมพ์ `/new` เพื่อเริ่มเรื่องใหม่ และ `/quit` เพื่อออก ใช้ `/new` เมื่อเปลี่ยนหัวข้อแล้วระบบยังยึดบริบทเดิม

เมื่อต้องการทดสอบ AI จริง ให้แก้ `.env` บนเครื่องตนเอง:

```dotenv
ANSWER_PROVIDER=gemini
GEMINI_API_KEY=ใส่กุญแจของคุณบนเครื่อง
GEMINI_MODEL=ชื่อโมเดลที่บัญชีของคุณเข้าถึงได้
```

ไม่ต้องส่งกุญแจผ่านแชต คำถามและเอกสารที่เลือกจะถูกส่งให้ Gemini โหมดนี้มีค่าใช้จ่ายตามบัญชี ยังไม่ได้ทดสอบกับบัญชีหรือโมเดลจริงของผู้ใช้

## ทดลอง API

```bash
uv run uvicorn voice_assistant.api:create_app --factory --host 127.0.0.1 --port 8000
```

`POST /ask` รับ `{"question":"...","session_id":null}` ส่ง `session_id` ที่ได้กลับมาเพื่อถามต่อ ทุกเส้นทางข้อมูลต้องใช้ `Authorization: Bearer <token ใน API_TOKENS_JSON>` ยกเว้น `/health` รายการปลั๊กอินอยู่ที่ `GET /plugins` และลบประวัติด้วย `DELETE /sessions/{session_id}` รุ่นนี้มี API และ CLI ยังไม่มีหน้าจอเว็บ

## การจัดการเอกสาร

เอกสาร Markdown 45 ไฟล์ใน `knowledge/source` คัดลอกจาก wsc2026 โดยเก็บเนื้อหาเดิม ดูที่มาใน `knowledge/PROVENANCE.md` เอกสารนำเข้านี้ยังไม่ได้รับการตรวจรับรองความถูกต้องหรือความเป็นปัจจุบัน

หลังเพิ่มหรือแก้เอกสาร ให้รัน:

```bash
uv run python scripts/publish.py
```

คำสั่งนี้ปรับรายการและลายนิ้วมือ SHA-256 เพื่อให้ทดลองค้นได้ โดยไม่ถือเป็นการอนุมัติใช้เนื้อหาจริง เก็บสถานะและช่วงวันใช้งานเดิมของรายการที่มีอยู่ แก้ `status` เป็น `draft` ใน `knowledge/publication.json` เพื่อพักเอกสาร หรือกำหนด `effective_from` / `effective_until` เป็นวันที่ ISO เอกสารใหม่ถูกเปิดให้ค้นในห้องทดลองตามค่าเริ่มต้น เมื่อเนื้อหาเปลี่ยน สถานะการตรวจเนื้อหาจะกลับเป็น `unverified_import`

## โครงสร้างและข้อจำกัด

`api.py` / `cli.py` → `service.py` → `registry.py` → `plugins/knowledge.py` → `providers.py` → ตรวจหลักฐาน → คำตอบ โดยมี `sessions.py` เก็บประวัติ

- ค้นด้วยคำภาษาอังกฤษและกลุ่มอักขระไทย 3 ตัว พร้อมจัดอันดับ BM25 และน้ำหนักชื่อเรื่อง เป็น lexical RAG เมื่อส่งผลค้นให้โมเดล ไม่มี embedding หรือ vector database
- ส่งเอกสารเต็มได้สูงสุด 3 ฉบับ รวมไม่เกิน 28,000 ตัวอักษร ข้ามเอกสารที่เกินขนาด ไม่ตัดเนื้อหาเงียบ ๆ ขนาดตัวอักษรไม่ใช่จำนวนโทเคน
- คำชี้กลับใช้กฎง่าย ๆ จึงอาจเลือกบริบทผิดเมื่อผู้ใช้เปลี่ยนเรื่อง ต้องประเมินกับบทสนทนาจริงก่อนเพิ่มความซับซ้อน
- ตรวจว่าแหล่งอ้างอิงอยู่ในเอกสารที่เลือกและข้อความอ้างตรงกับต้นฉบับ แต่ไม่ได้พิสูจน์ว่าการตีความของโมเดลถูกต้องทุกประโยค
- ประวัติเก็บใน SQLite เข้ารหัส เก็บบริบทล่าสุด 3 คู่สนทนา อายุเซสชัน 24 ชั่วโมงนับจากการบันทึกล่าสุด มีการแยกเจ้าของและป้องกันเทิร์นเขียนทับกัน ตัวตนใช้ token สำหรับห้องทดลอง ยังไม่ใช่ระบบบัญชีองค์กร
- ค้นไม่เจอจะบอกไม่พบ โมเดลล้มเหลวหรือหลักฐานผิดจะคืนสถานะเฉพาะ ไม่แสดงผลจำลองว่า AI ตอบสำเร็จ
- Registry รับสัญญาปลั๊กอินอ่านที่ประกาศ input/output/scope การเพิ่มปลั๊กอินไม่ต้องเพิ่มชื่อบริการใน registry การเรียกหลายเครื่องมือตามเจตนาและปลั๊กอินเขียนข้อมูลยังพักไว้

Gemini adapter ใช้ structured output ตาม [เอกสารทางการ](https://ai.google.dev/gemini-api/docs/structured-output) ต้องตรวจความเข้ากันได้กับโมเดลจริงก่อนใช้งาน

## ทดสอบและขั้นถัดไป

```bash
uv run pytest -q
uv run python scripts/evaluate_retrieval.py
```

รายละเอียดผลทดสอบอยู่ใน `docs/VALIDATION.md` ขั้นถัดไปคือทดสอบคำถามและคำถามต่อเนื่องจริง ตรวจเอกสารที่เลือก ความถูกต้องของคำตอบ และเวลาตอบ เมื่อ Knowledge ผ่านเกณฑ์ที่ตกลงกันจึงพิจารณาระบบเสียง ส่วน OMS/VOC และระบบภายนอกให้กลับมาทำผ่านปลั๊กอินเมื่อทราบสัญญาระบบจริง

รุ่นนี้อยู่บน branch `feat/knowledge-stability` ใน wsc2026 ใช้เอกสารร่วมจากรากรีโป ส่วนคำสั่งในหน้านี้รันจาก labs/knowledge เท่านั้น ไม่ได้เปิด OMS/VOC ใน runtime นี้
